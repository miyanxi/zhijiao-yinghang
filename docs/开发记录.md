# 智教英航开发记录

## 1. 开发目标

项目从高中英语教师的实际工作出发，目标不是做一个聊天机器人，而是做一个能记住学生学习历史、帮助教师完成“教—学—测—评—诊—干预—再评价”闭环的工作台。

## 2. 主要开发过程

第一阶段先梳理产品定位和核心业务链路，明确教师是服务对象，AI是助理，教师保留审核权。随后建立班级、学生、教学目标、教案、作业、学生作答和学习画像之间的数据关系，并用虚构种子数据验证真实数据流。

第二阶段完成首页、学生管理和学情分析，程序负责分数、正确率、完成率、趋势和关注规则。之后加入教学目标解析、教案生成、分模块重新生成、统一作业生成、题目检查、教师审核和发布。

第三阶段补充课后作业上传流程。教师上传与已发布作业对应的 Word 或 PDF，系统提取答案并形成待确认记录；教师确认后，程序按标准答案计算并写入学习记录，形成从课堂准备到学情更新的闭环。

第四阶段完善导出和本地运行能力，教案与作业支持 PDF、Word 下载，前端静态资源和后端可以打包为 Windows 本地程序。开发中用 Work Buddy 协助拆解需求、检查页面流程、修改提示词和生成代码；用 DeepSeek 处理教学目标理解、教案草稿和题目生成。

## 3. 开发原则

- 能由程序确定的事情交给程序，例如数据保存、计算、统计和状态流转。
- AI只负责理解、生成和分析建议，不能直接执行任意数据库操作。
- 重要教学内容采用草稿、教师审核、教师确认的流程。
- 作业以班级统一作业为主，不默认给每个学生生成不同作业。
- 先完成稳定、可演示的闭环，不在 MVP 阶段增加复杂架构。

## 5. 已知限制

该文档记录开发过程，当前入口和功能范围以根目录 README 与实际界面为准。旧专项训练、AI 总管家等模块保留部分历史实现，但已不在当前工作台导航中。

当前学生作业识别依赖可提取文字的 Word 或 PDF，图片扫描 OCR 尚未接入；AI生成内容仍需教师审核；本地 SQLite 适合比赛演示和小规模试用，不等同于学校正式部署；正式使用还需要身份认证、数据隔离和隐私保护。

比赛录屏用的 Windows 演示版另有显式开关 `ZHJ_DEMO_UPLOAD=1`：仅虚构的张同学上传 PDF 时使用与当前作业对应的预设示例答案。页面、上传记录和画像标注“演示模拟”，不宣称 PDF 内容已被识别。教师确认后仍由原有程序计分并更新画像；其他学生和默认源码运行仍走正常识别流程。
